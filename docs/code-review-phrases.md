# Code Review Phrases: Hacker Culture & L33t Speak Edition

## Classic Approval Phrases

### Mozilla/Firefox Style
- **r=me** - "reviewed by me" (the classic you mentioned!)
- **r+** - "reviewed, approved"
- **r- ** - "reviewed, needs changes"
- **r?** - "reviewed, needs clarification"

### Google Style
- **LGTM** - "Looks Good To Me"
- **LGTM+1** - "Looks Good To Me +1"
- **LGTM+2** - "Looks Good To Me +2" (stronger approval)
- **LGTM+1000** - "Looks Good To Me +1000" (extremely enthusiastic)

### GitHub Style
- **:+1:** - Thumbs up approval
- **:shipit:** - Ship it! (ready to merge)
- **:rocket:** - Ready for launch
- **:white_check_mark:** - Approved


### Rejection with Explanation
```

```

## Pro Tips

1. **Consistency**: Pick a style and stick with it in your team
2. **Context**: Use appropriate phrases for the type of change
3. **Tone**: Match the team culture - some teams prefer formal, others playful
4. **Clarity**: Always add comments for rejections or complex approvals
5. **History**: The classic `r=me` has been used since the early days of Mozilla

## Origin Stories

- **r=me**: Originated in Mozilla's Bugzilla system, where `r=` meant "reviewed by" and `me` was the reviewer's identifier
- **LGTM**: Became popular in open source projects, especially Google's code review system
- **:+1:**: GitHub's emoji system made this a standard approval indicator
- **:shipit:** - GitHub's "ship it" squirrel became a meme for "ready to merge"

Remember: The best code review phrase is one that your team understands and uses consistently! 🎯
